# Деплой на reg.ru VPS (без GitHub)

Пошаговая инструкция: арендуем свой сервер, вручную ставим на него
Node.js, заливаем файлы сайта напрямую (без GitHub), запускаем и
подключаем домен. Это «настоящее» системное администрирование —
именно то, чем занимаются на реальных хостингах.

## Шаг 1. Арендовать VPS

1. Зайди на [reg.ru/vps](https://www.reg.ru/vps/) → **Заказать VPS**.
2. Параметры для нашего сайта (он лёгкий, много ресурсов не нужно):
   - **ОС**: Ubuntu 22.04 (или 20.04)
   - Если есть готовый шаблон "Node.js" — можно выбрать его, но это не
     обязательно, поставим сами (Шаг 3).
   - **Тариф**: минимальный (1 CPU / 1 GB RAM хватает с запасом)
   - **Виртуализация**: KVM
3. После оплаты на почту/в личный кабинет придут:
   - **IP-адрес сервера**
   - **root-пароль** (или ты сам его задашь при заказе)

Сохрани эти данные — они понадобятся дальше.

## Шаг 2. Подключиться к серверу по SSH

На Windows 10/11 SSH-клиент уже встроен, отдельная программа не нужна.
Открой PowerShell и выполни:

```bash
ssh root@ТВОЙ_IP_АДРЕС
```

Подтверди подключение (`yes`), введи root-пароль (при вводе пароля
символы не отображаются — это нормально).

Если попал в приглашение вида `root@vps:~#` — подключение удалось.

## Шаг 3. Установить Node.js на сервер

Все команды дальше выполняются **на сервере**, внутри SSH-сессии.

```bash
apt update && apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v
npm -v
```

Должны увидеть версии Node.js 20.x и npm.

## Шаг 4. Перенести файлы сайта на сервер (без GitHub)

Самый простой способ для новичка — программа **WinSCP** (бесплатная,
Windows) с визуальным интерфейсом «перетащи и брось»:

1. Скачай и установи [WinSCP](https://winscp.net/eng/download.php).
2. Новое подключение: протокол **SFTP**, хост — твой IP, имя
   пользователя `root`, пароль — тот же, что и для SSH.
3. Слева — твой компьютер, справа — сервер. Перейди в папку `/root/`
   (или создай `/var/www/speakers`), справа.
4. Слева зайди в `C:\Claude code\AINIZER` и перетащи все файлы и папки
   **кроме** `node_modules`, `.git`, `.env`, `data/speakers.json`,
   `public/uploads/*` — их создадим/поставим заново на сервере.

Альтернатива для тех, кто предпочитает командную строку — `scp` прямо
из PowerShell (без WinSCP), одной командой с локальной машины:

```bash
scp -r "/c/Claude code/AINIZER" root@ТВОЙ_IP:/var/www/speakers
```

(лишние файлы потом можно удалить прямо на сервере через `rm -rf`).

## Шаг 5. Установить зависимости и настроить .env на сервере

Снова в SSH-сессии на сервере:

```bash
cd /var/www/speakers   # или /root/AINIZER — смотри, куда залил файлы
npm install --omit=dev
```

Создай `.env` прямо на сервере:

```bash
nano .env
```

Вставь (замени на свои значения):

```
ADMIN_PASSWORD=твой-настоящий-пароль
SESSION_SECRET=длинная-случайная-строка
PORT=3000
```

Сохранить в nano: `Ctrl+O`, `Enter`, выйти — `Ctrl+X`.

## Шаг 6. Запустить сайт через pm2 (чтобы не падал и жил после перезагрузки)

`pm2` — менеджер процессов, следит, чтобы Node.js-приложение работало
постоянно и само перезапускалось при сбое или перезагрузке сервера.

```bash
npm install -g pm2
pm2 start server.js --name speakers
pm2 save
pm2 startup
```

Команда `pm2 startup` выведет ещё одну команду — скопируй и выполни её
(это нужно один раз, чтобы pm2 стартовал автоматически при перезагрузке
сервера).

Проверить, что процесс жив:

```bash
pm2 status
pm2 logs speakers
```

На этом этапе сайт уже отвечает на порту 3000. Быстро проверить:

```bash
apt install -y ufw
ufw allow OpenSSH
ufw allow 3000
ufw enable
```

Открой в браузере `http://ТВОЙ_IP:3000` — должен открыться сайт.

## Шаг 7. Nginx — «правильный» вход через 80-й порт

На настоящих сайтах Node.js-приложение никогда не смотрит в интернет
напрямую — перед ним ставят **nginx** как reverse proxy: он принимает
обычные запросы на 80/443 порт и передаёт их приложению на 3000.

```bash
apt install -y nginx
nano /etc/nginx/sites-available/speakers
```

Вставь:

```nginx
server {
    listen 80;
    server_name ТВОЙ_IP_ИЛИ_ДОМЕН;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

Сохрани (`Ctrl+O`, `Enter`, `Ctrl+X`) и включи конфиг:

```bash
ln -s /etc/nginx/sites-available/speakers /etc/nginx/sites-enabled/
rm /etc/nginx/sites-enabled/default
nginx -t
systemctl restart nginx
```

Теперь закрой прямой доступ к 3000 снаружи (только через nginx):

```bash
ufw delete allow 3000
ufw allow "Nginx Full"
```

Проверь: `http://ТВОЙ_IP` (без `:3000`) должен показывать сайт.

## Шаг 8. Домен и DNS

1. Купи домен в личном кабинете reg.ru (если ещё не покупал) —
   **Домены → Зарегистрировать домен**.
2. В управлении DNS этого домена (reg.ru → мои домены → выбрать домен →
   **DNS-серверы и управление зоной**) добавь запись:
   - Тип: **A**
   - Хост: `@` (или пусто — это означает сам домен, например `мойдомен.ру`)
   - Значение: **IP-адрес твоего VPS**
   - Если нужен `www.мойдомен.ру` — добавь ещё одну A-запись с хостом `www`
3. Подожди обновления DNS (обычно от 10 минут до нескольких часов).
   Проверить: [dnschecker.org](https://dnschecker.org).
4. В конфиге nginx (Шаг 7) замени `server_name ТВОЙ_IP_ИЛИ_ДОМЕН;` на
   `server_name мойдомен.ру www.мойдомен.ру;` и перезапусти:
   ```bash
   systemctl restart nginx
   ```

## Шаг 9. HTTPS (бесплатный сертификат Let's Encrypt)

Когда домен уже указывает на сервер (Шаг 8 выполнен и DNS обновился):

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d мойдомен.ру -d www.мойдомен.ру
```

Certbot сам допишет конфиг nginx и настроит редирект на `https://`.
Дальше сертификат обновляется автоматически (certbot ставит для этого
таймер).

## Как обновлять сайт после изменений

Без GitHub процесс такой:

1. Меняешь код локально.
2. Заново заливаешь изменённые файлы через WinSCP (или `scp`).
3. На сервере:
   ```bash
   cd /var/www/speakers
   npm install --omit=dev   # если менялись зависимости
   pm2 restart speakers
   ```

## Важно про фото и данные

В отличие от Render, на своём VPS диск **постоянный** — фото и
`data/speakers.json` не пропадут при перезапуске. Это один из главных
плюсов своего сервера перед бесплатными serverless-хостингами.

Резервные копии всё равно стоит делать самому — например, периодически
скачивать папку `data/` и `public/uploads/` через WinSCP к себе на
компьютер.
