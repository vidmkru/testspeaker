# База спикеров — тренажёр по хостингу

Учебный проект: сайт со списком спикеров (фото, имя, должность, био).
Фото загружаются через простую админку. Цель — не сам сайт, а практика
полного цикла: **локальный запуск → Git/GitHub → деплой на хостинг →
свой домен и DNS**.

Есть два варианта деплоя:
- Через GitHub на Render.com — см. раздел 3 ниже (бесплатно, автодеплой).
- Напрямую на свой VPS (reg.ru), без GitHub, с ручной настройкой сервера — см. [DEPLOY_REGRU_VPS.md](DEPLOY_REGRU_VPS.md).

## Стек

- Node.js + Express — сервер
- EJS — шаблоны страниц
- JSON-файл (`data/speakers.json`) — «база данных» (специально максимально
  простая, без внешних сервисов — легко понять, что происходит)
- Multer — загрузка фото в `public/uploads/`
- express-session — простая защита админки паролем

## 1. Запуск локально

```bash
npm install
cp .env.example .env
```

Открой `.env` и поменяй `ADMIN_PASSWORD` на свой пароль. Потом:

```bash
npm run dev
```

Сайт: http://localhost:3000
Админка: http://localhost:3000/admin/login

Зайди в админку, нажми «Добавить спикера», загрузи фото — оно появится
на главной странице.

## 2. Заливаем код на GitHub

Хостинги (Render, Railway и др.) обычно деплоят сайт прямо из GitHub-репозитория.
Это первая часть тренировки.

1. Установи [Git](https://git-scm.com/downloads), если его ещё нет.
2. Зарегистрируйся на [github.com](https://github.com), если нет аккаунта.
3. Создай пустой репозиторий на GitHub (кнопка **New repository**), например `speakers-trainer`. Не добавляй README/gitignore — они уже есть локально.
4. В терминале, в папке проекта:

```bash
git init
git add .
git commit -m "Первая версия сайта-тренажёра"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/speakers-trainer.git
git push -u origin main
```

GitHub попросит авторизоваться — следуй подсказкам (обычно через браузер).

**Важно:** `.env` не попадёт в репозиторий (он в `.gitignore`) — это
правильно, пароли и секреты никогда не должны лежать в публичном коде.

## 3. Деплой на хостинг (бесплатный поддомен)

Рекомендуемый сервис для старта — **Render.com**: бесплатный план, не
нужна карта, деплой прямо из GitHub, готовый поддомен вида
`speakers-trainer.onrender.com`.

1. Зарегистрируйся на [render.com](https://render.com) (можно через GitHub-аккаунт — это и удобно, и сразу даёт доступ к репозиторию).
2. **New** → **Web Service** → выбери свой репозиторий `speakers-trainer`.
3. Настройки:
   - **Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
4. В разделе **Environment Variables** добавь:
   - `ADMIN_PASSWORD` = свой пароль
   - `SESSION_SECRET` = любая длинная случайная строка
5. Нажми **Create Web Service**. Через пару минут сайт будет доступен по
   адресу вида `https://speakers-trainer.onrender.com` — это и есть твой
   первый «настоящий» хостинг с публичным адресом.

Дальше при каждом `git push` в GitHub Render будет пересобирать и
обновлять сайт автоматически — это называется **CI/CD** (непрерывный деплой).

### Важное ограничение (и это тоже часть обучения!)

На бесплатном плане Render диск не постоянный: после перезапуска
контейнера (например, после «засыпания» из-за неактивности) загруженные
фото и `data/speakers.json` **обнулятся**. Это нормальная особенность
бесплатных serverless/эфемерных хостингов — на практике для таких данных
используют:

- отдельное файловое хранилище (S3, Cloudflare R2, Render Disks на платном плане),
- настоящую базу данных (Postgres, MongoDB и т.д.) вместо JSON-файла.

Для тренажёра это ок: ты увидишь эту особенность своими глазами — это
важный урок про то, чем «хостинг с диском» отличается от «безсостояньевого» (stateless) хостинга.

## 4. Домен и DNS (следующий шаг)

Когда освоишься с поддоменом `*.onrender.com`, можно потренироваться со
своим доменным именем:

1. Купи домен у регистратора (например, Namecheap, Reg.ru, Cloudflare Registrar) — от ~$10/год на популярных зонах.
2. В настройках сервиса (Render → Settings → Custom Domain) добавь свой домен — сервис покажет, какую DNS-запись нужно создать.
3. В панели регистратора (или там, где управляешь DNS-зоной домена) добавь запись:
   - **CNAME** — если поддомен (например `www.мойдомен.ru` → `speakers-trainer.onrender.com`)
   - **A-запись** — если корневой домен (`мойдомен.ru`) указывает на IP-адрес
4. Подожди обновления DNS (от нескольких минут до 24-48 часов — это называется **propagation**).
5. Проверить распространение записи можно на [dnschecker.org](https://dnschecker.org).

Это уже настоящая практика того, как домены связываются с хостингом —
ровно то же самое, что происходит у реальных сайтов.

## Структура проекта

```
server.js          — сервер и все маршруты
db.js               — работа с "базой" (JSON-файл)
data/speakers.json  — сами данные (создаётся автоматически)
views/               — HTML-шаблоны (EJS)
public/uploads/      — загруженные фото
public/css/          — стили
.env                 — секреты (пароль админки), не для Git
```

## Что попробовать дальше

- Заменить `data/speakers.json` на настоящую базу (например, Postgres на Render/Supabase).
- Подключить хранилище фото в облаке (S3/R2), чтобы фото не терялись при перезапуске.
- Настроить HTTPS с собственным доменом (Render делает это автоматически).
- Добавить второго администратора / логин по email вместо общего пароля.
